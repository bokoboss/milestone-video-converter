# Portable CCTV Converter v3

เครื่องมือแปลงชุดบันทึก Milestone/VideoOS เป็น MP4 สำหรับงานนับรถ เปิดด้วย `.bat` ไม่ต้องติดตั้ง Python, SDK หรือโปรแกรมของเราเป็น `.exe`

ดาวน์โหลดด้วย Code → Download ZIP แล้วแตก ZIP ก่อนเปิด setup.bat

## เริ่มใช้งาน

1. เปิด setup.bat โปรแกรมจะดาวน์โหลด FFmpeg/FFprobe 9.0.2 Essentials x64 จาก Gyan เมื่อไฟล์ยังไม่อยู่ใน tools และตรวจ SHA-256 ก่อนนำมาใช้ ขั้นนี้ต้องใช้อินเทอร์เน็ต
2. ใช้ชุดบันทึกที่ได้รับอนุญาตให้เข้าถึง โดยต้องมี `SmartClient-Player.exe`, `Client Files`, `.scp`, `.idx`, `.xml`, `.blk` และไลบรารี Player ที่มาด้วย โปรแกรมอ่าน Toolkit จากชุดนี้โดยตรง ไม่ต้องเปิดหรือติดตั้ง Player
3. ดับเบิลคลิก `setup.bat` แล้วเลือกโฟลเดอร์ชุดบันทึก รอข้อความ `PASS` หนึ่งครั้งต่อเครื่อง และตรวจอีกครั้งเมื่อเปลี่ยนชุดบันทึกเป็น Player คนละเวอร์ชัน
4. เปิด `start.bat` → เพิ่มโฟลเดอร์ → ติ๊กกล้องที่ต้องการ → เลือกปลายทาง **นอกโฟลเดอร์ต้นฉบับ** → กดเริ่มแปลง

ผู้ที่ได้รับโฟลเดอร์ portable converter ที่เตรียมไว้แล้ว setup จะใช้ไฟล์ FFmpeg ที่มีอยู่ ตรวจรายละเอียดสิทธิ์และแหล่งที่มาที่ [THIRD-PARTY.md](THIRD-PARTY.md)

ค่าเริ่มต้นรวมข้อมูลทั้งโฟลเดอร์เป็นไฟล์เดียวต่อกล้อง เลือกแบ่งไฟล์ 10/15/30/60/120 นาที หรือพิมพ์จำนวนนาทีเต็มบวกเองได้ เลือก “รวมข้ามโฟลเดอร์” เมื่อต้องการต่อช่วงเวลาของกล้องเดียวกัน

หลายเครื่องทำงานได้โดยแบ่งโฟลเดอร์ต้นทางให้แต่ละเครื่อง แล้วตั้งปลายทางคนละโฟลเดอร์ ไม่ใช้พื้นที่งานชั่วคราวร่วมกัน แนะนำให้แปลงบนดิสก์ภายในเครื่องก่อน แล้วคัดลอกผลลัพธ์ภายหลัง

## คุณภาพและเวลา

- ใช้ Toolkit อ่านฐานข้อมูลตามดัชนี แล้วใช้ FFmpeg แบบ `-c copy` ไม่เข้ารหัสวิดีโอใหม่ ไม่ลดความละเอียด ไม่ลดเฟรมเรต ไม่เติมภาพดำ และไม่เร่งวิดีโอ
- MP4 เป็นภาชนะบรรจุ ขนาดจึงใกล้วิดีโอที่บีบอัดอยู่เดิม การลดขนาดมากกว่านี้ต้องใช้การบีบอัดใหม่ ซึ่งเครื่องมือนี้ไม่ทำ
- นับเฟรมและเก็บเวลาจากฐานข้อมูลต้นทางครบก่อน export แล้วตรวจจำนวนและ timestamp ของข้อมูลส่งออก ไม่คัดลอก payload มาทำ hash ซ้ำในขั้น scan
- ค่าเริ่มต้น “เร็ว: ตรวจสตรีมครบ + สุ่มภาพ”: เทียบ SHA-256 รายแพ็กเก็ตครบทั้งไฟล์หลังปรับ H.264/H.265 ให้เป็นรูปแบบ Annex B เดียวกัน ตรวจลำดับและเวลา PTS/DTS แล้วเทียบภาพที่ถอดรหัสต้นทางกับปลายทางในช่วงประมาณ 2 วินาทีที่ต้น กลาง ท้าย และก่อน–หลังช่วงภาพขาด โดยรวมช่วงที่ซ้ำกัน
- “ละเอียด: ตรวจภาพทุกเฟรม”: เปรียบเทียบ SHA-256 ของภาพที่ถอดรหัสครบทั้งไฟล์ ใช้เมื่อต้องตรวจการถอดรหัสทุกภาพหรือ codec ไม่รองรับโหมดเร็ว โปรแกรมไม่เปลี่ยนไปโหมดละเอียดที่ใช้เวลานานให้อัตโนมัติ
- หากโหมดเร็วพบ codec ที่ไม่รองรับหรือสตรีมไม่ตรง จะเก็บ MKV พร้อมแจ้งตรวจสอบ ให้เลือกโหมดละเอียดเองเมื่อต้องการ ไม่ทิ้งข้อมูลหรือรับรอง MP4 ที่ตรวจไม่ผ่าน
- แบ่งไฟล์เฉพาะตามระยะเวลาที่ผู้ใช้เลือก ตัดที่ keyframe โดยยึดขอบเวลาจากต้นช่วง จึงอาจคลาดเล็กน้อย ไม่สร้างไฟล์เปล่าสำหรับช่วงขาด และรวมหางสั้นไม่เกิน 2 วินาที (หรือ 1% ของช่วงที่เลือก ถ้าน้อยกว่า) ไว้ในไฟล์ก่อนหน้าเพื่อไม่ให้เกิดไฟล์เศษจาก boundary GOP
- ช่วงภาพขาดตรวจจากระยะห่างเฟรมที่มากกว่า `max(3 × ค่ามัธยฐานช่วงเฟรม, ค่ามัธยฐาน + 0.1 วินาที)` ช่วงเฟรมปกติคำนวณจากสูงสุด 10,000 ช่วงแรก ไม่ได้อ้างว่าเป็นการตรวจทุกเฟรมที่กล้องควรบันทึกแต่ไม่ได้บันทึก
- ไม่แยกไฟล์เมื่อพบช่วงภาพขาด เก็บ timestamp เดิมไว้ใน MP4 และบันทึกช่วงขาดในรายงาน ตัวเล่นอาจค้างภาพสุดท้ายระหว่างช่วงนั้น แอพนับรถควรอิง timestamp ของเฟรมแทนการสมมติว่าทุกวินาทีมีภาพครบ
- หากมีหลายสตรีมที่รวมแบบไม่บีบอัดซ้ำไม่ได้ หรือการตรวจภาพไม่ผ่าน ให้เก็บ MKV และแจ้งตรวจสอบ ไม่แยกไฟล์เพิ่มเอง
- การรวมข้ามชุดใช้ Camera ID และเวลา UTC จากข้อมูลจริง ตรวจเวลาซ้ำก่อนเริ่ม หากชุดของกล้องหนึ่งทับกัน กลุ่มนั้นจะถูกพัก แต่กล้องอื่นยังทำต่อได้
- รวมเฉพาะช่วงที่ต่อเนื่องภายใน 2 มิลลิวินาที และ codec/configuration เข้ากันได้ ผลที่รวมต้องผ่านการตรวจ hash และจังหวะเวลาซ้ำอีกครั้ง
- รายงานเวลาเป็น UTC พร้อมข้อมูลอ้างอิง +07:00 ชื่อไฟล์และเวลาในหน้าต่างแสดงประเทศไทย ไม่อิง timezone ของเครื่อง

## ความเร็วของ inspect

รุ่นนี้อ่านข้อมูลแพ็กเก็ตและ keyframe โดยไม่ใช้ `-show_frames` ถอดรหัสทุกภาพในขั้น inspect และไม่อ่านนับแพ็กเก็ตต้นทางซ้ำอีกหนึ่งรอบ ขั้นนี้แสดงเวลาที่ผ่านไปพร้อมปริมาณ metadata ที่อ่านแล้ว ใน v3 ขั้น verify แบบเร็วตรวจข้อมูลบีบอัดครบและถอดรหัสเฉพาะช่วงตัวอย่าง โดยปิดการปรับขนาดภาพอัตโนมัติ โหมดละเอียดจึงเป็นโหมดเดียวที่เทียบภาพทุกเฟรม

ผลทดสอบการวางแผนไฟล์จากชุดตัวอย่าง: รวม = 1; 10 นาที = 12; 15 = 8; 30 = 4; 60 = 2; 120 = 1 เวลาตรวจจริงขึ้นกับเครื่องและดิสก์

ผลวัดส่วน verify บนคลิปจริง 1080p ยาว 10 นาที: โหมดเร็ว 8.34 วินาที เทียบกับโหมดละเอียด 260.61 วินาที (ประมาณ 3.2% ของเวลาเดิม) ตัวเลขนี้ไม่รวม scan/export/remux และไม่ใช่คำรับรองเวลาแปลงรวมของทุกเครื่อง การ export ผ่าน Toolkit และการอ่านเขียนดิสก์ยังใช้เวลา

การรวมข้ามโฟลเดอร์นำ packet manifest ที่ตรวจผ่านแล้วกลับมาใช้เป็นข้อมูลอ้างอิง ตรวจผลรวมอีกครั้งโดยไม่ถอดรหัสต้นทางเต็มชุดซ้ำ หากรายงานรุ่นเก่าไม่มี manifest จะอ่านแพ็กเก็ตบีบอัดของไฟล์นั้นหนึ่งรอบเพื่อสร้างข้อมูลอ้างอิง

โปรแกรมที่เปิดค้างและงานที่เริ่มก่อนอัปเดตยังใช้ค่ารุ่นเดิม หลังจบคิวให้ปิดโปรแกรมแล้วเปิด `start.bat` ใหม่เพื่อเห็นตัวเลือกรุ่นใหม่

## ผลลัพธ์

แต่ละงานมีโฟลเดอร์ `job_<รหัสไม่ซ้ำ>` และแต่ละคิวมี `queue_<รหัสไม่ซ้ำ>`:

- `*.mp4` และ `status: verified` ใน `report.json`: ผ่านการตรวจแล้ว
- `original_preserved.mkv` และ `status: needs_review`: เก็บสตรีมส่งออกครบไว้ แต่ยังรับรองผล MP4 ไม่ได้ ให้อ่าน `error` ในรายงาน
- `*.partial.mp4` / `original.partial.mkv`: งานยังไม่เสร็จหรือถูกยกเลิก **ห้ามใช้เป็นผลที่ตรวจผ่าน**
- `report.json` schema version 2: `verification.mode` / `verificationMode` ระบุ `stream_sample` หรือ `decoded_full`; มี `packetSha256`, `packetManifest`, `decodedSamples`, เวลาแต่ละขั้นใน `timings` และข้อมูลกล้อง/ไฟล์
- `pixelSha256` / `pixelManifest` มีค่าเมื่อเลือกตรวจภาพครบเท่านั้น โหมดเร็วใช้ค่า `null` เพื่อไม่อ้างว่าตรวจภาพทุกเฟรม
- `firstOutputPts` คือเวลาเฟรมแรกใน container: เทียบเวลาจริงด้วย `beginUtc + (PTS - firstOutputPts)` โดยเฉพาะไฟล์ที่มี B-frames
- `timeline.compressedPayloadSha256` ของรุ่นใหม่เป็น `null` เพราะเลิกทำ hash payload ใน scan ซึ่งไม่ได้ใช้ตรวจ MP4 โดยยังตรวจจำนวนเฟรมและเวลาต้นทางครบ
- `conversion.log` / `merge.log`: คำสั่งและข้อผิดพลาดสำหรับตรวจสอบ
- `queue-report.json`: สรุปทุกงานในคิว

หากรวมข้ามโฟลเดอร์ จะได้ `merged_<รหัสไม่ซ้ำ>` เพิ่ม โดยเก็บไฟล์ที่ตรวจผ่านรายชุดไว้ด้วย จึงใช้พื้นที่มากขึ้น สามารถลบไฟล์รายชุดที่ไม่ต้องการได้เองหลังตรวจผลรวมแล้ว

## ความพร้อมของเครื่อง

- Windows 64 บิต พร้อม Windows PowerShell 5.1, .NET Framework และ Windows Forms ที่ใช้งานได้
- ใช้กระบวนการ PowerShell 32/64 บิตให้ตรงกับไลบรารีของแต่ละชุดบันทึก งานถูกแยกเป็นกระบวนการเพื่อไม่โหลด Toolkit คนละเวอร์ชันปนกัน
- ต้องมีพื้นที่ว่างอย่างน้อยประมาณ 3 เท่าขนาด `.blk` บวก 1 GB สำหรับการแปลงรายชุด การรวมข้ามชุดใช้พื้นที่เพิ่มสำหรับสำเนาผลรวม
- ดาวน์โหลดเฉพาะตอน setup เมื่อขาด FFmpeg ไม่แก้ Registry, PATH, ExecutionPolicy ไม่ขอสิทธิ์แอดมิน และไม่ข้ามนโยบายองค์กร
- หาก PowerShell ถูกองค์กรบล็อก โปรแกรมจะใช้งานไม่ได้บนเครื่องนั้น การใช้ `.bat` ไม่ได้ทำให้ข้อจำกัดองค์กรหายไป ให้อ่านข้อผิดพลาดจาก `setup.bat`
- ถ้า Toolkit ขาด dependency หรือชุดบันทึกเข้ารหัสด้วยรหัสผ่าน เครื่องมือจะแจ้งข้อผิดพลาด ยังไม่มีหน้าต่างรับรหัสผ่าน

## ขอบเขตที่ตรวจแล้วและข้อจำกัด

ทดสอบกับชุด Milestone/VideoOS ที่มี MediaStorage `.blk` + ดัชนีและโปรเจกต์ `.scp` ไม่รองรับ `.blk` ของผู้ผลิตอื่นโดยอัตโนมัติ ชุดที่ไม่มี Player/Toolkit หรือใช้โครงสร้างฐานข้อมูลอื่นจะถูกปฏิเสธอย่างชัดเจน

MP4 รองรับเส้นทางที่ทดสอบสำหรับ H.264 และมีการตรวจจริงก่อนรับรอง codec อื่น ไม่ทิ้ง track ที่มีภาพ หากมีหลาย video track ที่ทำงานซ้อนเวลา หรือข้อมูลมี timestamp เรียงย้อน จะไม่เดาว่าต้องใช้ภาพใด

โหมดเร็วตรวจความตรงกันของข้อมูลบีบอัดครบทั้งหมดและภาพในช่วงตัวอย่าง ไม่ได้ทดลองถอดรหัสภาพทุกเฟรม จึงไม่รับรองว่าทุกส่วนของวิดีโอต้นฉบับปราศจากปัญหาการถอดรหัส โหมดละเอียดใช้ SHA-256 ของภาพครบทั้งไฟล์ ส่วน `.blk` → MKV อาศัย Toolkit ส่งออกแบบไม่แปลงภาพ พร้อมตรวจจำนวนเฟรมและ timestamp ไม่ได้ถอดรหัส `.blk` ด้วยตัวอ่านอิสระอีกตัวหนึ่ง

ยังต้องตรวจบนคอมพิวเตอร์เครื่องที่สอง ชุดบันทึกช่วงเวลาอื่นจริง และตัวอ่านของแอพนับรถ จึงยังไม่รับรองว่า dependency และนโยบายของทุกเครื่องเหมือนเครื่องพัฒนานี้

## ตรวจซ้ำสำหรับผู้ดูแล

เปิด `test.bat` เพื่อรันทดสอบเดิมและชุด v3 (H.264/H.265, packet/hash/time mutations, การแบ่งที่ keyframe และ cache สำหรับการรวม) ในโฟลเดอร์ `tests` ไม่แตะต้นฉบับ ทดสอบ path, XML, ขอบเขตไฟล์, ช่วงขาดที่คงอยู่ในไฟล์เดียว, รูปแบบภาพเปลี่ยน, การแบ่งตามระยะเวลาที่เลือก, เวลาซ้ำ, การยกเลิก, ไฟล์เสีย, MP4 แบบ lossless และการต่อคลิป พร้อมเก็บตัวอย่างทดสอบไว้ตรวจย้อนหลัง

รายละเอียดซอฟต์แวร์ภายนอกอยู่ใน `THIRD-PARTY.md` และ `tools` เครื่องมือพัฒนาและข้อมูลกล้องจริงไม่รวมอยู่ใน ZIP แจกจ่าย
